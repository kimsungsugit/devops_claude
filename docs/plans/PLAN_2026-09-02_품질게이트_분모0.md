# 라운드 15 — 품질 게이트가 **못 잰 축을 0%로 채점**해 실패시켰다

## 착수 실측

라운드 14 는 `.validation.md` 만 고쳤다. 같은 모듈의 나머지 두 리더
(`read_gate_report` / `read_confidence_report`)를 **진짜 라이터로 만든 파일**에 태워 보니
전 필드가 정상 복원됐다 — 라벨 불일치는 `.validation.md` 한정이었다. (재확인 완료)

대신 그 프로브가 다른 것을 드러냈다. 흠 없는 픽스처(설명 100%·입력 100%·ASIL 주석·
Related SRS)인데 `Gate pass: False`, 그리고 `Output fill: 0 / 0 (0.0%)`.

### 실제 산출물 전수 조사 (127개 `.quality_gate.md`)

| | |
|---|---|
| 분모 0 지표가 있는 리포트 | **29개** |
| 그중 `Gate pass` | **29개 전부 False** |
| 가장 흔한 축 | `Input fill` 29 · `Output fill` 29 |

**실제 429함수 KJPDS02_PV 산출물**:

```
- Total functions: `429`
- Gate pass: `False`
- Gates: `5` / `13` passed
- Input fill:  `0` / `0` (0.0%)     ← 분모 0
- Output fill: `0` / `0` (0.0%)     ← 분모 0
```

실패로 계상된 8개 중 **2개가 잴 수 없는 축**이다. 리포트 어디에도 "못 쟀다"는 표시가
없어, 읽는 사람은 8개 모두를 고칠 거리로 읽는다.

### 왜 분모가 0인가 — 문서를 열어 확인했다

```
r2: ['Name', ..., 'g_sysos_wdictrl']      ← SwUFn_0102 는 **전역 변수** 항목
r3: ['Prototype', ..., '']                 ← 비어 있다
```

429행 중 prototype 이 있는 행은 **2개**(둘 다 `void main( void )`). 즉 이 문서의 SwUFn
항목은 상당수가 함수가 아니라 변수이고, prototype 이 없으니 입력/출력 슬롯을 셀 수 없다.
**"해당 없음"이 아니라 "잴 수 없음"** 이다.

`_rate(v, base) = 0.0 if base <= 0` 가 그 둘을 같은 0.0 으로 접고,
`failed = [k for k, v in metrics.items() if v < gate[k]]` 가 그걸 실패로 센다.

이 저장소가 이미 같은 형태를 고쳤다 — SwITCV 게이트가 문서가 재지 않는 축으로 채점해
**영구 FAIL + 진짜 미달 25건 은폐**(`project_swit_coverage_gate_axis`). 여기도 같다:
영구 실패 2건이 섞이면 `Gate pass: False` 가 정보를 잃는다.

## 개선 — 범위를 닫고 간다

`report_gen/validation.py::generate_uds_field_quality_gate_report`

1. `_rate` → `Optional[float]`. 분모 ≤ 0 이면 **`None`(미측정)**, 0.0 이 아니다.
2. `failed` 는 **잰 것 중** 임계 미달만. `unmeasured` 를 따로 모은다.
3. 지표 줄: `(0.0%)` → `(미측정 — 분모 0)`.
4. `- Gates: \`P\` / \`M\` passed` 에서 **M = 잰 지표 수**, `- Unmeasured gates: \`U\`` 추가.
5. `## Unmeasured Gates` 절 신설 — 무엇을 왜 못 쟀는지.
6. `Gate pass` 는 **보수 방향 유지**: 실패가 있거나 **미측정이 있으면 False**.
   미측정을 통과로 접지 않는다(`gate_report.py` 의 "판정 불가는 통과가 아님"과 같은 결).
   → 실 산출물의 판정은 **안 바뀐다**. 바뀌는 것은 "왜 False 인가" 다.
7. **개선 권고문에도 같은 출구가 생긴다** — 미측정을 `failed` 에서 빼면
   `Total functions: 0` 문서(실 산출물 4건)에서 `failed` 가 비어
   "모든 품질 게이트를 통과했습니다" 가 나갈 수 있다. 구판에서는 그 문서도 실패 7건을
   달고 있어 안 나갔다(실제 파일로 확인) — **이번 수정이 새로 만들 뻔한 거짓**이다.
   `if unmeasured:` 분기를 앞에 둔다. 판정 값을 고치면 그 값을 말로 옮기는 산문도 본다.

`report_gen/evidence.py::read_gate_report` — `unmeasured_gates` 노출.
`DocGenStatusBoard.jsx` — "게이트 항목 5 / 11 통과 · 미측정 2".

### 다운스트림 영향 = 0 (추적해서 확인함)

`.md` 의 괄호 안에 `%` 가 없으면 `parse_gate_report` 가 이미 `percent=None` 을 내고
`to_rate_map` 이 그 키를 건너뛴다. 그래서 사이드카 유래 `rates` 에서 `input_fill` 이 빠진다.

**그 `rates` 가 어디로 가는지 끝까지 따라가 보니 채점엔 안 쓰인다**
(`backend/helpers/uds.py:858` `report_gate` → `864-865` 는 `gate_pass`/`status` 만 읽고,
`897` 에서 응답에 실릴 뿐이다). 그리고 `gate_pass` 는 이 수정으로 안 바뀐다.

> ⚠ **하네스 정합 오류를 하나 겪었다(기록).** 처음엔 사이드카 `rates` 를
> `_derive_quality_reason_codes` 에 직접 먹여 "미측정이 `INPUT_PARSE_LOW` 로 샌다",
> "ASIL 100% 인데 `ASIL_LOW` 가 뜬다" 는 결론을 냈다. **둘 다 틀렸다** — 그 함수는
> 사이드카가 아니라 **payload 기반 `_compute_quick_quality_gate`** 의 `quick_gate` 를
> 받는다(`uds.py:860`). 재현 하네스에 라이브와 다른 shape 을 먹이면 결론이 반대로 나온다.
> `workflow/quality/evaluator.py` 도 같은 payload 기반 `quick_gate` 를 읽으므로 무영향.
