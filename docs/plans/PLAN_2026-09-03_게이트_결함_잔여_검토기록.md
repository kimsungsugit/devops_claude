## 0. Context — 왜 이 계획인가

사용자 요청: *"게이트 관련된거를 진행중이야. 잘못된 부분들은 개선해야하고, 추가로 작업해야할거 계획 작성해야하고,
승인 계획서도 추가해서 계획서 작성해줘."* — "승인 계획서" = **검토 기록(승인) 기능**(§6-1 후보 22 의 G5~G7) 계획으로 확인.

게이트는 세 층이다. 세 층 모두 "게이트가 **사실**을 재는가" 를 반복해 고쳐 왔고, 이번엔 감사 3축(준비 게이트 / 품질 게이트 / 미해결·하네스 인벤토리)으로 남은 것을 전수 수집했다.

| 층 | 무엇 | 감사 결과 |
|---|---|---|
| **준비 게이트** | 생성 전 입력·상한·템플릿·직전 결말 공시 — `backend/routers/docgen_preflight.py`(2,075줄) + `DocGenPreflightPanel.jsx` | 확정 10 · 유력 11 · 의심 9 |
| **품질 게이트** | 산출물 채점·사이드카·증거·조회 — `report_gen/validation.py`·`evidence.py`·`workflow/quality/*`·`QualityGateSection.jsx` | 확정 16 · 유력 8 · 의심 6 |
| **하네스·문서** | pre-commit·CI·가드·CLAUDE.md 수치 | 확정 5 · 판단 축 4 |

세 보고의 공통 결함 형태는 이 저장소가 이미 이름 붙인 것들이다 — **미측정을 0/False/missing 으로 접기**, **게이트가 이름 대는 것 ≠ 실제로 쓰이는 것**, **라이터가 쓰는데 리더가 안 읽음**, **판정 복제(두 화면·두 임계)**, **낡은 주석이 사실 행세**.

## 4. Part C — 승인 계획서: 검토 기록(승인) 기능 G5~G7

### 4.1 무엇을 만드나 / 안 만드나

**만든다** — 게이트 조회 화면(`QualityGateSection` 🚦 실행 이력)에서 run 하나를 골라 사람이 **판정(approved / rejected / needs_work) + 사유**를
남기고, 그 기록이 **어느 바이트의 산출물**에 대한 것인지 해시로 고정되며, 이력이 감사행과 함께 조회된다.

**안 만든다**(§6-1 비목표 그대로) — 필드 단위 승인(CORE-000 선행 요구가 됨) · DOCX 본문 편집 · 최상위 탭 · **게이트화**(검토 결과로 FAIL 을
만들지 않음) · 챗 승인 테이블 재사용 · `/api/local/editor/*` 재사용. 어휘는 **'검토 기록'** 으로 고정(S14 — '승인' 은 실행을 뜻하지 않는다).

⚠ 순서상 **Q-6 다음**이다 — 판정 표시가 세 표면에서 갈린 채로 "무엇에 승인했는가" 를 기록하면 기록 자체가 모순을 담는다.
