# STS·SUTS·SITS 레퍼런스 초과 품질 실행계획

작성: 2026-09-21. 상태: 진행 중. 최종 목표는 형식 재현이 아니라, 같은 대상·입력에서 정본보다 더 많은 실제 결함을 찾아내는 시험 명세 생성이다.

## 완료 기준

1. STS는 요구의 범위·단위·상태·시간·허용오차에 근거한 관측 가능한 판정 조건을 갖는다.
2. SUTS는 입력 도메인과 기대 출력의 근거를 구분한다. 타입 범위나 변수명만으로 확정 기대값을 만들지 않는다. 복합 결정의 MC/DC 독립 영향 쌍은 실제 식 평가로 검증한다.
3. SITS는 모듈 호출 목록을 넘어 데이터 전달·상태 변화·실패 전파·시간 조건을 검증한다. 실행 전제와 주입 지점, 관측 지점을 명시한다.
4. 미지원·미측정·추정·실행 입증을 구분하고 XLSM, 품질 보고서, API, UI, 실행 패키지까지 유지한다. 빈 칸 채우기나 TC 개수 증가는 우월성의 증거로 쓰지 않는다.
5. 동일 프로젝트·소스 revision·요구/설계/템플릿 해시를 고정해 정본/기존 생성/개선 생성을 비교한다. 결함 탐지율·잘못된 기대값·실행 가능률·요구 커버리지·MC/DC 및 조합 커버리지·중복·생성 시간과 검토 부담을 각각 공개한다.
6. 정본이 검출하는 결함을 유지하고 추가 결함을 검출한다. 비교 불가능하거나 실행하지 않은 항목은 미입증으로 남긴다. 이 기준 전부를 확인하기 전 전체 완료로 선언하지 않는다.

## 설계 원칙과 리스크

- 정확한 근거를 늘리는 것과 잘못된 확신을 줄이는 것을 함께 진행한다. 추정값을 전부 비우는 것만으로 고도화를 완료하지 않는다.
- 소스 계산은 코드 일관성 oracle이며 요구 적합성 oracle를 대체하지 않는다. 구현의 버그를 기대값으로 복제하지 않게 독립 요구/설계 oracle와 비교한다.
- C의 타입·signedness·오버플로우·포인터·매크로·단락평가를 모르면 해석 성공으로 위장하지 않는다. 지원 문법/예산/미지원 사유를 기록한다.
- 시험 가능한 입력과 타입 밖 주입값을 구별한다. U8의 -1/256은 그대로 실행 가능한 U8 값이 아니며 주입 위치와 변환을 명시해야 한다.
- 기존 정본 형식/추적 ID는 유지하되 잘못된 기대값과 기법 주장은 호환성을 이유로 보존하지 않는다. 변경 전후 차이를 기록한다.
- 안전 소스 코드는 수정하지 않는다. 안전 관련 시험의 실패 기대를 통과 목적으로 변경하지 않는다.

## 검증·리뷰 운영

계획→설계→구현→독립 tester→deep reviewer 순서로 진행한다. 변경 모듈 테스트 후 통합/전체 회귀를 수행한다. 실제 파일 readback과 사용자가 사용하는 호출 경로까지 확인한다. 기존 품질 점수는 보조 지표이며 의미적 정확성 gate를 대신하지 못한다. 각 단계에서 결과/잔여 작업을 이 문서에 갱신한다.

## P0 진행 기록 (2026-09-21)

- 실제 정본 read-only 추출: STS 59 / SUTS 420 / SITS 77 고유 TC ID. 각 ID의 시트·셀 위치와 파일 SHA-256을 `.codex_tmp/capability_eval/reference_manifest.json`에 기록했다.
- 소스 루트의 C/H 99개 파일 해시를 기록했다. 정본과 소스 revision 대응은 미확인이라 우월성 비교는 아직 성립하지 않는다.
- SUDS 이름 검색의 4개 후보에는 비교 노트 2개와 가공 템플릿 1개가 포함돼 있었다. 원본 문서 확장자·가공 템플릿 제외를 적용해 정본 1개로 좁혔다. 이 필터 근거를 manifest 스크립트에 남겼다.
- Gate 1 planner와 Gate 2 architect 독립 검토 완료. 기존 logic_flow는 대입문을 생략하고 return 식을 절단하므로 정확 계산의 입력으로 사용하지 않는다.

## P1 설계 결정

공통 `test_evidence` 계약은 각 기대 열마다 status(derived/specified/proposed/unknown/conflict), oracle_kind(source/requirement/design/ai/none), 값·원문 근거·사유를 보존한다. 기존 expected는 사람이 읽는 표시값으로 유지한다. 미상 숫자는 확정값으로 내보내지 않는다. 실행 여부는 별도로 not_run으로 기록한다.

`c_test_semantics`는 전체 원문 AST가 지원 문법인지 먼저 검증한다. 첫 지원은 명시적 정수 타입의 return·단순 산술·if/else·local 대입이다. 호출·포인터·volatile·static·미해결 매크로·정의되지 않은 overflow는 거부한다. 소스 계산을 요구 충족 증명으로 표시하지 않는다. SUTS의 일반·void early return·AI 갱신 경로 모두 동일 계약을 거쳐야 한다.

MC/DC는 별도 P2로 진행하며, 실제 변수 입력을 평가해 다른 원자 조건이 고정된 상태에서 대상 조건과 결정값이 바뀌는 쌍을 찾는다. 원문 결정별 occurrence·단락 관측·예산 절단을 기록하고 출력 상한 적용 후 남은 시험쌍을 다시 검증한다.

### 소스 버전 확인

로컬 SVN 작업 사본은 revision 1020, last-changed 2025-03-18T05:59:00.686248Z이며 `svn status --quiet` 출력은 없었다. 시험 정본 파일명은 STS 2023-01-16, SUTS 2024-02-21, SITS 2024-02-19이므로 동일 revision임을 추정하지 않는다. P6은 요구 변경분/적용 함수 범위 정합 또는 당시 소스 revision 확보 후 비교해야 한다.

### 독립 의미 평가 기준선

`scripts/test_generation_semantic_baseline.py`는 기존 품질 지표와 분리된 합성 QM 사례 평가다. 정확한 산술 기대값, 동작 누락의 명시, OR/AND 독립 영향 쌍을 실제 생성 데이터로 평가한다. 미충족 시 종료 코드 1과 항목별 반례를 출력한다. 별도 detector 테스트는 잘못된 사례를 실제로 거부하는지 확인한다. 합성 사례의 성공을 실제 프로젝트 정본보다 우수하다는 결론으로 확대하지 않는다.
