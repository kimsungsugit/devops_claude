# STS·SUTS·SITS 레퍼런스 초과 품질 실행계획

작성: 2026-09-21. 상태: 진행 중. 최종 목표는 형식 재현이 아니라, 같은 대상·입력에서 정본보다 더 많은 실제 결함을 찾아내는 시험 명세 생성이다.

## 완료 기준

1. STS는 요구의 범위·단위·상태·시간·허용오차에 근거한 관측 가능한 판정 조건을 갖는다.
2. SUTS는 입력 도메인과 기대 출력의 근거를 구분한다. 타입 범위나 변수명만으로 확정 기대값을 만들지 않는다. 복합 결정의 MC/DC 독립 영향 쌍은 실제 식 평가로 검증한다.
3. SITS는 모듈 호출 목록을 넘어 데이터 전달·상태 변화·실패 전파·시간 조건을 검증한다. 실행 전제와 주입 지점, 관측 지점을 명시한다.
4. 미지원·미측정·추정·실행 입증을 구분하고 XLSM, 품질 보고서, API, UI, 실행 패키지까지 유지한다. 빈 칸 채우기나 TC 개수 증가는 우월성의 증거로 쓰지 않는다.
5. 동일 프로젝트·소스 revision·요구/설계/템플릿 해시를 고정해 정본/기존 생성/개선 생성을 비교한다. 결함 탐지율·잘못된 기대값·실행 가능률·요구 커버리지·MC/DC 및 조합 커버리지·중복·생성 시간과 검토 부담을 각각 공개한다.
6. 정본이 검출하는 결함을 유지하고 추가 결함을 검출한다. 비교 불가능하거나 실행하지 않은 항목은 미입증으로 남긴다. 이 기준 전부를 확인하기 전 전체 완료로 선언하지 않는다.

## 기준선과 확인된 결손

- 2026-09-21 생성기/프로파일/설계근거 관련 7개 테스트 파일: 423 passed / 46.42초. 이는 기존 계약의 회귀 결과이며 시험 설계의 우월성을 입증하지 않는다.
- SUTS 기대값 추론은 로직 없이 uint8 상한 초과에 255를 반환한다. SITS는 타입과 입출력 이름만으로 수치 기대값을 생성한다.
- SUTS MC/DC는 조건 추출 뒤 baseline/개별 토글을 생성하나 복합 결정 결과와 독립 영향을 검증하지 않는다. 실제 토글 경로는 다른 변수를 중간값으로 놓으므로 baseline과의 일관성도 별도 검증해야 한다.
- recommended의 현재 근거 강화 효과는 STS에 한정된다. extended는 물량 상한을 풀지만 기대값 정확성의 증거는 아니다.
- 실제 HDPDM01 정본은 docs/ 및 D:/Project/devops/260105/docs/에 존재한다. KJPDS02 등 별도 프로젝트를 섞어 정량 우월성을 주장하지 않는다.
- Cloudium 원본은 읽기 전용. 실 소스·원본 문서·사용자 설정은 변경하지 않는다.

## 설계 원칙과 리스크

- 정확한 근거를 늘리는 것과 잘못된 확신을 줄이는 것을 함께 진행한다. 추정값을 전부 비우는 것만으로 고도화를 완료하지 않는다.
- 소스 계산은 코드 일관성 oracle이며 요구 적합성 oracle를 대체하지 않는다. 구현의 버그를 기대값으로 복제하지 않게 독립 요구/설계 oracle와 비교한다.
- C의 타입·signedness·오버플로우·포인터·매크로·단락평가를 모르면 해석 성공으로 위장하지 않는다. 지원 문법/예산/미지원 사유를 기록한다.
- 시험 가능한 입력과 타입 밖 주입값을 구별한다. U8의 -1/256은 그대로 실행 가능한 U8 값이 아니며 주입 위치와 변환을 명시해야 한다.
- 기존 정본 형식/추적 ID는 유지하되 잘못된 기대값과 기법 주장은 호환성을 이유로 보존하지 않는다. 변경 전후 차이를 기록한다.
- 안전 소스 코드는 수정하지 않는다. 안전 관련 시험의 실패 기대를 통과 목적으로 변경하지 않는다.

## 검증·리뷰 운영

계획→설계→구현→독립 tester→deep reviewer 순서로 진행한다. 변경 모듈 테스트 후 통합/전체 회귀를 수행한다. 실제 파일 readback과 사용자가 사용하는 호출 경로까지 확인한다. 기존 품질 점수는 보조 지표이며 의미적 정확성 gate를 대신하지 못한다. 각 단계에서 결과/잔여 작업을 이 문서에 갱신한다.
