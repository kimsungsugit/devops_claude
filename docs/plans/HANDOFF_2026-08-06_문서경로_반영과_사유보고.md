## 3. 지금 코드가 이렇게 되어 있다

### 연결 문서 진실원
- `frontend-v2/src/scmLinkedDocs.js` — **단일 출처**. `useRegistryLinkedDocs(scmId, snapshot, enabled)`.
  - `SCM_REGISTRY_EVENT` 구독 + `window` focus 구독으로 재조회.
  - 값이 같으면 **같은 객체 참조 유지**(alt-tab 마다 `loadMatrix` 재생성 방지).
  - 소비자 2곳: `SrsSdsSection.jsx`, `ProjectSummarySection.jsx`. **복제하지 말 것.**
- `Settings.jsx` 의 register/update/delete **3경로 전부** `notifyScmRegistryChanged()` 호출.

### 설정값이 SCM 을 가리는 것 표면화
- `sharedInputs.js` → `normDocPath()`, `docPathsOverridingScm()`.
- 우선순위 `설정 > SCM` 자체는 **의도된 정책**(직접 입력을 덮지 않는다). 바꾸지 말 것.
  가려졌다는 **사실만** 배지(`설정 우선`)와 `SCM 값 따르기` 버튼으로 노출.
- 해소는 SCM 값 **복사가 아니라 설정 키 삭제** — 복사하면 그 순간 또 굳는다.

### 실패 사유 보고
- `backend/services/resolver_helpers.py`
  - `read_requirement_doc()` — **Path 직독**. cloudium U: 를 못 읽지만 사유는 정확. 7곳에서 사용.
  - `read_requirement_doc_via_resolver()` — **resolver(worker IPC) 경유**. 실제로 읽힌다.
  - `read_uploaded_requirement_doc()` — 업로드 바이트용. temp write/파싱/unlink 한 덩어리.
  - ⚠ 셋은 대체재가 아니다. **사유 문구만 공유**해야 화면에서 같은 말로 보인다.
- `GET /api/scm/linked-docs-status/{id}` (`backend/routers/scm.py`) — 레지스트리 경로 **전용**.
  사용자 제출 경로를 받지 않으므로 새 입력 표면이 없다. 확인 실패는 `exists: null`(모름).
- 프론트 0건 분기는 **3상태**로 갈린다: 경로 미지정 / 못 읽음(사유) / 읽었는데 0건.
  `SrsSdsSection.jsx` 와 `traceMatrix.js` **양쪽 문구가 같아야 한다.**

## 4. 다음 세션이 절대 하면 안 되는 것

| 금지 | 이유 |
|---|---|
| `config/scm_registry.json` 을 커밋하거나 되돌리기 | **사용자가 직접 편집하는 사용자 데이터**. 현재 uncommitted 상태가 정상이다 |
| `read_only=True` 만 남기고 `_GridSheet` 제거 | O(행²) 폭주. read_only 이전보다 **더 나쁘다** |
| `useRegistryLinkedDocs` 를 컴포넌트에 복제 | 이 결함이 정확히 그렇게 생겼다. 훅 하나만 고친다 |
| 문서 경로 우선순위를 `SCM > 설정` 으로 뒤집기 | 의도된 정책. 직접 입력을 덮으면 안 된다 |
| 확인 실패를 `exists: false` 로 접기 | IPC 한 번 실패에 멀쩡한 문서가 '없음'이 된다 |
| `git commit -- <paths>` | 동시 세션 방어가 **아니다**(index 기반, 실사고 5회). `git add` 후 pathspec 없이 `git commit -F` |

## 7. 이 작업에서 배운 것 (다음에 또 나온다)

1. **가드를 짤 때 "무엇이 달라지는가"를 봐야 한다.** "언마운트 후 재조회 없음" 단언은
   리스너 누수를 못 잡는다(언마운트되면 조회 effect 자체가 사라져 호출이 안 는다).
   리스너 add/remove **쌍**을 핸들러 참조까지 대조해야 잡힌다.
2. **구조 검사만으로는 부족하다.** "함수가 호출된다" + "문자열이 파일에 있다" 두 검사가
   모두 통과하는데도 경로 분기의 사유 수집을 지운 뮤테이션이 생존했다(문자열이 업로드
   분기 덕에 남았다). **엔드포인트까지 태우는 테스트**가 있어야 한다.
3. **`res.ok` 를 검사해도 else 가 비면 침묵이다.** X9 체크리스트가 "res.ok 검사 여부"만
   보면 이걸 놓친다.
4. **측정이 먼저다.** "SUTS 가 안 바뀐다"는 사실 36초였고, "SRS 가 없다"는 사실 맞았다.
   추측으로 고쳤으면 둘 다 엉뚱한 곳을 고쳤을 것이다.
5. **ruff ASYNC240 ratchet 이 실제로 일을 했다.** 새 blocking 을 async 핸들러에 얹으려던
   걸 막았고, 규칙을 피하는 대신 진짜로 워커 스레드로 내렸다.
