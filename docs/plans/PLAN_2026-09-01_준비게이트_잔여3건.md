## 착수 실측 — 계획을 세우기 전에 잰 것

| 확인 대상 | 기록돼 있던 것 | **실측** |
|---|---|---|
| 재시도 사다리 예산 | full 2400s / 1800s / 900s | **7200 / 3600 / 1800**(`config.py:201`) |
| 종결 체크포인트의 시작 시각 | — | **없다**(`started_at` 은 `started` 레코드에만, 덮어써져 사라진다) |
| `local.py` UDS 템플릿 | 원 경로 그대로 넘김 | 그대로 확인(`local.py:1221`, `local_uds_generate`) |
| 실패 3건의 원인 마지막 줄 | `PackageNotFoundError` | 그대로 확인 — 경로가 **`U:/…`** 다 |

⚠ 첫 줄이 이 계획의 성격을 바꾼다. 예산 2400s 는 `_generate_docx_with_retry` 안의
**죽은 리터럴 폴백**이고 실제 값은 그 3배다. 메모리가 그 리터럴을 옮겨 적어 "full
스테이지가 위험하다" 를 3배 과장했다 — 같은 값을 두 곳에 두면 한쪽이 반드시 낡는다는
이 저장소의 재발 패턴 그대로다.

## P1 — `/api/local/uds/generate` 만 템플릿을 로컬화하지 않는다

`local.py:1221` 이 `resolve_registered_uds_template()` 의 **원 경로**를 그대로
`_generate_docx_with_retry` 에 넘긴다. 생성은 서브프로세스에서 `docx.Document(path)`
로 직접 여니 worker 가 없다 → `U:` 등록본이면 3단계 전부 `PackageNotFoundError`.

**그 실패는 가정이 아니다.** 캐시에 남은 08-10·08-11 기록의 마지막 줄이 정확히 그
모양이고(경로가 `U:/연구소/…/01.SwUDS/(XXXX_SwUDS)…docx`), 그 경로는 라운드 7이
jenkins 쪽을 `resolve_template_for` 로 배선해 고쳤다. **local 쪽만 남았다.**

- 지금 잠복인 이유: 등록본이 로컬 `D:` 이고 프론트 호출처 0곳.
- 조치: 등록본 분기에 `resolve_builder_input(..., label="UDS 템플릿")` 한 줄.
  업로드 템플릿 분기는 이미 로컬 tmp 라 그대로 둔다.
- 해석 실패는 `None`(= 템플릿 없이 생성)로 **사유와 함께** — 조용히 원 경로를
  흘려보내면 지금과 같은 실패가 하류에서 난다.

## P2 — 생성이 얼마나 걸렸는지 아무도 기록하지 않는다

체크포인트는 단계마다 **덮어쓰이고**, 종결 레코드(`success`/`failed`/`timeout`/
`exception`)엔 `ended_at` 만 있다. `started_at` 은 `started` 레코드에 있다가 지워진다
→ **소요를 되살릴 방법이 없다.** 그래서 "다음 생성이 예산 안에 들어오는가" 를 물을
수단 자체가 없었다.

1. **라이터**: 종결 레코드 4갈래 전부에 `started_at` 과 `elapsed_seconds` 를 싣는다.
   시작 시각은 단계 시작 시 한 번 잡아 그대로 옮긴다(다시 재지 않는다).
2. **사다리 단일 출처**: `getattr(config, …, [(…,2400),…])` 의 리터럴 폴백을 없앤다.
   낡은 복제가 이미 한 번 사람을 속였다.
3. **리더**: `docgen_last_run` 이 `elapsed_seconds` · `timeout_seconds` · 그 단계의
   **예산**(config 직독)을 요약에 싣는다.
4. **게이트**: `history` 행이 소요와 예산을 **나란히** 말한다.
   판정은 **측정된 것만** — `timeout` 이었거나 `elapsed ≥ 예산의 80%` 일 때만 경고로
   올린다. 소스 파일 수로 다음 실행을 **추정하지 않는다**(이 저장소의 `unmeasured`
   규약과 같은 결 — 모르는 것은 모른다고 적는다).

## P3 — 정본에만 있는 남의 함수 969개 (판단 축 → 선택지)

정본 템플릿은 heading 1,035개를 갖고 오는데 payload 는 57개다. 나머지는 빈
`[ Function Information ]` 서식으로 남는다(문서 행의 23%). `empty_heading_count` 로
**세고는 있으나 지우지 않는다** — 정본을 부분집합으로 쓰는 것이 의도일 수 있어서다.

판단 축은 이 저장소의 관례대로 **선택지로 만든다**(`template_source`·`suts_scope` 와
같은 `choices` 표). 기본값은 현행 유지라 **산출물은 고르기 전까지 바뀌지 않는다**.

| 값 | 뜻 |
|---|---|
| `keep`(기본) | 지금 그대로 — 빈 서식이 남아 "분석되지 않았다" 를 드러낸다 |
| `drop` | payload 에 없는 SwUFn heading 과 그 표를 **쓰지 않는다** |

- 생성기: `_note_fn_match` 가 이미 4갈래로 분류하므로 그 판정을 **재사용**한다
  (규칙 복제 금지). `(삭제)` 표기 heading 은 지금도 별도 축이라 건드리지 않는다.
- 관측량 신설: `dropped_heading_count` — "지웠다" 와 "비워 뒀다" 는 다른 사실이다.
- 게이트: 직전 생성의 `empty_heading_count` 로 "지난번 N개가 빈 서식으로 남았습니다"
  를 말해 **고를 근거**를 같이 준다(라운드 11 의 `history` 행 재사용).

## 확인된 리스크

- **P3 는 문서 구조를 크게 바꾼다.** 기본값을 `keep` 으로 두어 고르기 전에는 산출물이
  불변이다. 회귀 판단 기준은 `matched_functions` 불변 + `dropped + empty` 합 보존.
- **P2 의 `elapsed_seconds` 는 단계 하나의 소요다.** 사다리 전체 소요가 아니다 —
  체크포인트가 단계마다 덮어써지므로 앞 단계의 소요는 원래부터 남지 않는다.
  그 사실을 문장에 적는다(합계로 읽히면 거짓이 된다).
- **P1 의 해석 실패 시 동작이 바뀐다.** 지금은 원 경로로 넘어가 하류에서 죽고, 고치면
  템플릿 없이 생성된다. 후자가 낫지만 **조용하면 안 된다** → 사유 로그 필수.
