## 1. 왜 이걸 했나

직전 커밋 `e29bd0e`(경로 이탈 봉인)·`d13f3b6`(산출물 경로 선점)에서 드러난 **결함 패턴**이

## 2. 실측 결과 (스캐너는 scratchpad 에 있다)

### 축 B — 의도한 4xx 가 500 으로 위장 → **4곳** (수정함)

라이브 재현:

    V.vcast_download_report("no_such.xlsx")   → 500 "Download error: 404: Report file not found"
    V.vcast_download_report("../../../x.xlsx") → 500 "Download error: path traversal not allowed"

`except Exception` 이 `try` 안의 `HTTPException` 을 먹고 500 으로 다시 던지고 있었다.
결과 셋: ①클라이언트가 자기 입력 문제를 서버 장애로 읽는다 ②모니터링에 없는 장애가 쌓여
진짜 장애가 묻힌다 ③`str(e)` 가 응답에 실려 내부 절대경로가 샌다.

**⚠ 처음 스캔은 49건이라 했는데 정밀화하니 4건이었다.** 줄어든 이유를 기록해 둔다 —
①중첩 함수(SSE `_run()` 등) 안의 raise 는 바깥 try 로 안 흐른다(45건) ②`safe_resolve_under`
의 ValueError 를 **400 으로** 바꾸는 14곳은 결함이 아니다(이탈은 진짜 클라이언트 오류).

⚠ 그 사이에 **0건이 나온 판이 한 번 있었다** — 핸들러가 500짜리 `HTTPException` 을
**생성**하는 걸 "HTTPException 을 처리함"으로 오인해서다. 전수 판정이 한쪽으로 100% 몰리면
데이터가 아니라 조회 경로를 의심할 것.

### ⚠ 이 검증에서 내가 세 번 틀렸다 (다음 세션이 반복하지 않도록)

1. **탐침 URL 이 틀렸다.** `/api/vcast/download-report/...` 를 때렸는데 실제 라우트는
   `/api/vcast/reports/{filename}` 이다. 틀린 URL 도 **404** 를 돌려줬고 나는 그걸
   "의도한 404 복원됨"으로 **PASS 로 셌다**. 본문(`API endpoint not found`)을 안 봤으면
   가짜 초록으로 끝났다. → **상태코드만 보지 말고 본문으로 핸들러 도달을 확인할 것.**
   (이 저장소 기록상 "조회 경로 오류" **7번째**다.)
2. **`/tmp/...` 를 이탈 경로로 줬다.** Windows 네이티브 파이썬은 그걸 현재 드라이브
   루트로 풀어 `C:\tmp\...` 에 썼는데, 내 `ls` 는 MSYS `/tmp` 를 봐서 **"생성 0건"**
   이라고 보고했다. 하마터면 "봉인 성공"의 근거로 쓸 뻔했다.
   → 경로 탐침은 **네이티브 경로**로 주고, 검사도 같은 해석으로 할 것.
3. **그래서 실제로 파일을 또 흘렸다** (`C:\tmp\axisA_3kzI\pwned_9102.pdf` 19KB, 삭제 완료).
   이 시리즈에서 이탈 탐침이 진짜로 이탈한 게 **세 번째**다.
