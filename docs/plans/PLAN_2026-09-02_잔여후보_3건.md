## 라운드 20 — `read_excerpt` 가 4년째 삼켜 온 실패의 정체

### 무엇이 문제인가

`workflow/common.py::read_excerpt` 는 실패하면 `""` 를 돌려주고, 그 `""` 는
`workflow/ai.py:2276·2310·3391` · `workflow/pipeline.py:1578·3268` 에서 **AI 입력으로
그대로 간다**. 즉 "코드를 못 읽었다"가 "코드가 비어 있다"로 전달된다.

라운드 19 에서 `except OSError` 로 좁혔더니 `pytest -n auto` 워커가 죽었다
(`ValueError: I/O operation on closed file`, 대조군으로 3회 재현). **이 자리엔
OSError 아닌 실패가 실제로 난다**는 뜻이고, 맨 `except:` 가 그걸 계속 덮고 있었다.

### 접근 — 좁히는 대신 **기록한다**

정체를 모른 채 범위를 좁히면 조용하던 결함이 크래시로 바뀐다(R19 실증). 그래서
동작(`""` 반환)은 그대로 두고 **삼킨 예외를 관측 가능하게** 만든다.

- `_record_swallowed(p, exc)` — `ARIA_READ_EXCERPT_TRACE` 설정 시에만 파일에 append.
  미설정이면 운영 부담 0.
- ⚠ **로거가 아니라 파일**이다. 유력 후보가 `I/O operation on closed file` 이라
  stdout 에 쓰면 계측기 자신이 같은 실패로 죽어 아무 기록도 안 남는다.
- ⚠ 계측기는 자기 실패를 삼킨다 — 본 흐름을 절대 안 깬다.

### 순서

1. 계측 삽입 → 스모크(고의 `ValueError` 가 기록되는가) ✔
2. `pytest tests/ -n auto` 1회 전량 실행, `rx.log.<pid>` 수집
3. 정체 확정 → **근본 수정** → 그 다음에 범위 좁히기 재시도
4. 좁힐 수 없으면 그 이유를 코드에 남기고 **계측만 영구화**

### 성공 기준

"OSError 아닌 실패"의 **예외형·발생 지점·호출자**를 이름으로 댈 수 있어야 한다.
못 대면 그 사실을 그대로 적는다(추정으로 좁히지 않는다).

## 라운드 22 — 죽은 필드가 아니라 죽은 엔드포인트였다

### 실측이 후보의 성격을 바꿨다

후보는 "`safety_pct`/`safety_total`/`safety_covered` 가 `local.py` 에서 계산되는데
읽는 곳이 없다"였다. 맞다. 그런데 더 큰 사실이 있다:

```
backend/routers/local.py:1851  @router.post("/api/local/traceability")   ← 호출자 0
```

| 대상 | 결과 |
|---|---|
| frontend-v2 전체 | `/api/local/traceability` **0회** |
| tests | **0회** |
| 실제 추적성 UI 가 부르는 것 | 전부 `/api/jenkins/uds/*` (모드 무관) |

즉 `safety_*` 는 **죽은 엔드포인트 안의 죽은 필드**다.

### 세 갈래로 확인할 것

1. **분모 결함(잠복)** — `round(safety_covered / max(safety_total, 1) * 100, 1)`.
   ASIL 요구가 0건이면 `safety_pct = 0.0` = "안전 커버리지 0%"로 읽힌다.
   **미측정을 0 으로 뒤집는** R15/R17 과 같은 계열. `local.py` 에 같은 형태가
   `coverage_pct` · `full_coverage_pct` · `suts_function_coverage_pct` 까지 **4곳**.
   → 라이브 경로(`jenkins.py:4026` `coverage_pct ... else 0.0`)에도 같은 형태가
   있는지 대조하고, **살아 있는 쪽부터** 고친다.

2. **모드 간 계약 불일치** — R18 과 같은 형태다.
   `jenkins.py` cache_payload 만 `asil_distribution`·`asil_has`·`asil_gap_count`·
   `asil_unknown_count`·`band_counts` 를 낸다. 프론트는 이 키들로 ASIL 카드
   (`ResultPanel:354`)·밴드 KPI(`SummaryOverviewTab:157`)·파이프라인 건강도
   (`pipelineHealth.js:18,78`)를 그린다. `local.py` 에는 **하나도 없다**.
   → local 경로가 그 표면을 먹이는지 확인. 먹인다면 **local 모드에서 ASIL 카드가
   통째로 사라진다**(사용자 가시 결함). 안 먹인다면 죽은 사본 증거가 하나 더.

3. **테스트가 죽은 사본을 지킨다** — `tests/unit/test_sds_trace_purification.py:172`
   가 `safety_pct` 존재를 단언한다. 그 테스트가 검증하는 SDS 정화 lockstep 이
   **살아 있는 경로에서도** 성립하는지 확인한다. 안 하면 "시험이 있다"가
   거짓 안심이 된다(R18·integration 401 사건과 같은 형태).

### 처리 방침

- **삭제를 기본으로 두지 않는다.** ASIL 안전 요구 커버리지는 ISO 26262 맥락의 핵심
  지표다. 계산이 옳다면 **살아 있는 경로로 옮기는 것**이 맞다.
- 옮기기 전에 **분모부터 고친다**. 지금 배선하면 없던 거짓 신호를 만든다.
- 죽은 엔드포인트를 지우는지 남기는지는 위 2번 결과에 달렸다 — 실측 후 결정.

## R20 — **계획의 전제가 뒤집혔다**

계획은 "OSError 아닌 실패의 정체를 규명한다"였다. 계측 결과 **그런 실패는 없었다.**

못했다. 대조군이 있다고 해서 옳은 축을 가른 건 아니다.

→ 최종형: `except OSError` 로 좁히되 삼킨 것은 `_record_swallowed` 로 **관측 가능**하게 둔다
